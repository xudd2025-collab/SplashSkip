# v0.6.19 通用控件文字模型

`train_control_text.py` 在电脑训练 640 → 32 → 2 的 TFLite 分类器，输出“关闭广告”和“广告”。输入为实际候选文字裁剪，不包含宣传正文。字体、字号、明暗、抗锯齿、留白和像素偏移由固定种子生成；负例包括关闭网页、广告设置、继续播放、取消和其他用途文字。六种合法安装的中文字体由用户电脑提供，不打包字体文件。

生成数据的训练／验证样本分别生成；它们不是完全未知字体评估。优酷、爱奇艺两张真实截图完全不参与训练，在 `ControlTextCheck` 中作为独立来源检查，并移动按钮、替换正文和缩放分辨率。验证不能代表所有软件、字体或机型。早期留出宋体检查存在大量漏识别，最终将宋体纳入训练；这不是宣称解决了所有陌生字体。

生产还要求实际四个字、按钮边界和合理前缀结束，防止“关闭广告功能”被截成关闭操作。清楚字形的模型门槛 0.90；低分辨率笔画较弱时模型门槛提高到 0.98。普通叉号、静音图标和无关闭按钮的广告不属于此语义规则。广告标签输出只用来筛选候选，仍需要独立字形核验。


实际数据不上传。现有跳过与关闭／叉号模型保留；NPU 选择及手机总点击耗时没有通过本轮真机验证。

# 模型训练

通用跳过模型独立对跳过按钮评分，旧模型保留关闭与叉号输出。错误文字检查发现旧模型对“路过”存在过高分数，已改为不让旧模型高分覆盖通用模型的拒绝。跳过的两个字符也分别检查。通用模型加载失败时暂停截图跳过，保留普通无障碍控件识别。

v0.6.18 新增按钮笔画背景分离与近期特征排序，沿用原模型，不将本轮宣传正文加入训练。近期特征仅从手势完成后两张独立截图检查得到；不是在线更新神经网络权重。复杂背景下两个跳过字的笔画都须通过，二值按钮输入由原模型重新评分。启动提示文字只在腾讯视频和虎牙启动窗口内作为补充广告证据，普通通用入口仍要求广告标签。电脑检查使用相同二值输入与两个实际权重文件；电脑耗时不能代替手机发现至完成点击的时延。

v0.6.17 沿用 v0.6.14 原按钮模型与 v0.6.15 通用补充模型；本次未把宣传正文加入训练。明暗笔画与字符分组用于提出候选，模型和独立“跳过”字形确认文字。“广告”模板由字体直接渲染，仅保留两个字的笔画及少量边距；分别核验两个字符后才认可标签。48 组替换宣传正文、多分辨率、删除按钮/标签以及非广告文字检查在电脑完成；真实一秒目标必须另用手机录屏核对。

`train_skip_model.py` 公开当前分类器的 NumPy 训练与 TFLite 导出实现：32 × 20 灰度输入，标准化后展平，16 个 ReLU 隐藏单元和一个 sigmoid 输出。随机种子固定，训练 1200 步。它只判断候选裁剪是否包含跳过文字，不是通用 OCR。

原始采集数据含个人页面，因此不公开；缺少相同数据不能复现当前模型的完全相同权重。公开仓库包含现有 `skip_text.tflite`，构建 APK 无需再次训练。

## 虎牙与腾讯视频按钮模型

`train_action_model.py` 训练新增的 `ad_action.tflite`：32 × 20 灰度输入、32 个 ReLU 隐藏单元、三个 sigmoid 输出，分别识别“跳过”“关闭”和叉号。使用平衡小批次 Adam 训练 1800 步。APK 的 `AdActionRegion` 决定与训练一致的裁剪区域，按当前规则选用对应类别，概率至少 0.85 才接受。

这个模型判断按钮字形，不能仅靠一个叉号判断广告。生产代码先验证完整已适配场景、前台和开关，再运行按钮模型；正常电视剧推荐页的叉号仍由场景检查排除。模型加载失败时记录日志，使用已有完整场景规则。支持 NNAPI 的系统会尝试委托推理，实际是否使用 NPU 取决于驱动；没有支持时使用 CPU。

训练清单沿用上面的 `file`、`box`、`label`、`split`，另加 `source`（原始截图来源组）和 `action`（`skip`、`close` 或 `cross`）。同一来源不能同时进入训练集和验证集。字体合成样本另设来源组；同一截图的增强裁剪不是独立广告样本。示例：

```json
{"file":"ad.png","box":[1034,165,1150,227],"label":1,"action":"skip","source":"capture-a","split":"train"}
```

```powershell
python tools/train_action_model.py --dataset C:\private\dataset.json --output C:\private\candidate.tflite --report C:\private\report.json
```

验证不通过时不会导出候选模型；中间权重只供本地分析。还需通过 `ActionModelCheck.java` 导出生产匹配器实际定位的多尺寸按钮裁剪，再用 `check_action_model.py --model C:\private\candidate.tflite --crops C:\private\production-crops` 检查实际候选。通过后再替换 APK 资产，避免训练分数与生产裁剪不一致。
